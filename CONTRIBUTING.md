# Contributing

Please open an issue describing a concrete research question, defect, or proposed experiment before a substantial change. Small corrections can be submitted directly.

Use Python 3.10 or newer and run `python -m unittest discover -s tests -v`. Keep the initial baseline dependency-free. Add tests for new behavior, including invalid inputs and boundary cases. Document units, assumptions, determinism, and limitations.

For empirical claims, provide the provenance required by docs/EVALUATION.md. Label synthetic data and planned work. Do not present unit-test outputs as network benchmarks. Avoid trivial or duplicate submissions intended to increase contribution counts.

Submit only work you have the right to license under MIT. Preserve third-party notices and identify sources. Use accurate Git author information and describe material assistance in the pull request when relevant; do not falsely claim sole authorship. Maintainers are responsible for reviewing submitted work, including tool-assisted changes.

Be respectful, focus criticism on evidence, and remove credentials and personal data from reports. Do not post exploitable security details or sensitive traffic in public issues; until a private reporting channel exists, ask for a safe reporting route without including the details.
